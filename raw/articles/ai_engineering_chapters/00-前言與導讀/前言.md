# 前言

> 即使是我2017年的一個使用語言模型評估翻譯品質的小專案（MEWR，automatic machine translation evaluation metric without reference text，無參考文字的自動化機器翻譯評估指標），也得出了我們需要「更好的語言模型」的結論。

> 論文的作者之一Ilya Sutskever後來聯合創立了OpenAI，並透過GPT模型將這一理念變為現實。

當ChatGPT問世時，我和許多同行一樣，一時有些無所適從。讓我吃驚的並不是模型的規模或能力，因為十多年來，AI社群一直知道擴大模型規模會提升其效能。早在2012年，AlexNet的作者就在他們的里程碑式論文"ImageNet Classification with Deep Convolutional Neural Networks"中指出：「我們所有的實驗都表明，只要有更快的GPU和更大規模的資料集出現，我們的結果就能得到進一步改善。」

讓我真正吃驚的是，模型效能的小幅提升，竟然能解鎖如此之多令人難以置信的新應用。我本以為模型品質提高一點，應用場景最多也只會增加一點，但現實卻是應用場景迎來了爆炸式增長。

這些新的AI能力不僅增加了對AI應用的需求，也降低了開發者的准入門檻。現在構建AI應用變得非常容易，甚至無須編寫任何程式碼即可建立應用。這種轉變使AI從一個專業學科變成了每個人都能使用的強大的開發工具。

儘管如今的AI應用看起來很新穎，但其實它們建立在已經存在多年的技術之上。早在20世紀50年代，就已經出現了關於語言建模的論文。我們現在所說的RAG（retrieval augmented generation，檢索增強生成）應用所依賴的檢索技術，早在RAG這一術語出現之前，就已經被廣泛用於搜尋和推薦系統。部署傳統ML（machine learning，機器學習）應用的最佳實踐——系統性的實驗、嚴格的評估，以及對模型速度和成本的持續最佳化——在基於基礎模型（foundation model）構建應用時依然適用。

許多人或許會因為AI工程（AI engineering）技術看起來熟悉且易用，便覺得AI工程沒有什麼新東西。然而，儘管構建AI應用的許多原則保持不變，但AI模型的規模和能力的提升帶來了新的機遇和挑戰，也需要新的解決方案。

本書涵蓋了將基礎模型應用於解決現實問題的端到端過程，既包括其他工程領域久經考驗的技術，也包括隨著基礎模型興起而湧現的新技術。

我寫這本書的初衷是為了學習，而我也確實獲益良多。我從自己參與的專案、閱讀的論文以及採訪物件那裡學到了很多。在撰寫本書的過程中，我參考了超過100次對話和採訪的筆記，受訪者包括來自主要AI實驗室（OpenAI、谷歌、Anthropic等）的研究人員、框架開發者（NVIDIA、Meta、Hugging Face、Anyscale、LangChain、LlamaIndex等）、不同規模的公司的高管和AI/資料部門負責人、產品經理、社群研究人員，以及獨立應用開發者（參見前言最後的「致謝」部分）。

我尤其從早期讀者那裡學到了很多。他們檢驗了我的假設，向我展示了不同的視角，並讓我接觸到了新的問題和方法。在將本書中的一些章節分享在我的同名部落格Chip Huyen上之後，我收到了來自社群的幾千條評論，其中許多評論為我提供了新的視角或驗證了我的假設。

我希望在本書交到你手中之後，這段學習之旅能繼續下去，因為你擁有獨特的經驗和視角。如果你對本書有任何回饋，請隨時透過我的X帳號、LinkedIn帳號或電子郵箱（hi@huyenchip.com）與我聯絡。

## 本書內容簡介

本書提供了一個框架，用於將基礎模型（包括大語言模型LLM和多模態大模型LMM）適配到具體的應用中。

構建AI應用的方法多種多樣，本書概述了各種解決方案，並提出了一些問題，幫助你評估哪種方案最適合你的需求。本書能夠幫助你回答的問題包括：

- 我是否應該構建這個AI應用？
- 如何評估我的應用？能否使用AI來評估AI的輸出？
- 什麼導致出現了幻覺（hallucination）？如何檢測和緩解幻覺問題？
- 提示工程（prompt engineering）的最佳實踐是什麼？
- 為什麼RAG有效？有哪些實施RAG的策略？
- 什麼是智慧體（agent）？如何構建和評估智慧體？
- 什麼時候應該微調（finetune）模型？什麼時候不應該微調模型？
- 我需要多少資料？如何驗證資料的品質？
- 如何讓我的模型更快、更便宜、更安全？
- 如何構建回饋迴圈，不斷改進我的應用？

本書還將幫助你釐清紛繁複雜的AI領域，包括模型型別、評估基準測試，以及看似無窮無盡的應用場景和應用模式。

書中的內容透過案例研究進行說明，其中許多案例是我親自參與的，並輔以大量參考文獻支撐，且經過了不同背景的專家的全面審閱。本書雖耗時兩年撰寫，但它凝聚了我過去10年在語言模型和ML系統方面的經驗。

> 2017年我教授TensorFlow課程時，深刻體會到工具和教程更新之快，令人痛苦。

與我之前出版的O'Reilly圖書《機器學習系統設計》（*Designing Machine Learning Systems*，DMLS）一樣，本書關注的是AI工程的基礎知識，而非具體的工具或API。工具更新換代很快，底層知識的生命力更為持久。

## 如何結合《機器學習系統設計》（DMLS）閱讀本書

本書可以作為DMLS的配套讀物。DMLS側重於基於傳統ML模型構建應用，涉及更多表格資料標註、特徵工程和模型訓練。本書則側重於基於基礎模型構建應用，涉及更多提示工程、上下文構建和參數高效微調。這兩本書都是獨立且模組化的，因此你也可以單獨閱讀任意一本。

由於基礎模型本質上也是ML模型，因此一些概念對兩者都適用。如果某個主題與本書相關，但已在DMLS中進行了廣泛討論，本書仍會涉及，但篇幅較小，並會提供相關參考資料。

請注意，DMLS涵蓋了許多本書未涉及的主題，反之亦然。本書第1章也介紹了傳統ML工程與AI工程之間的差異。現實世界的系統往往同時涉及傳統ML模型和基礎模型，因此掌握兩者的相關知識通常是必要的。

判斷一本書裡的知識能否經得起時間考驗並非易事。我主要依靠以下三條標準。

第一，看一個問題到底是源於AI工作方式的根本侷限，還是說等模型變得更強，這個問題自然就消失了。如果是根本侷限，我就會深入分析它背後的挑戰，以及應對每種挑戰的方案。我個人非常推崇「由簡入繁」的方法，因此對於很多問題，我會從最簡單的方案入手，隨後再逐步過渡到更複雜的方案，從而應對不斷升級的挑戰。

第二，請教大量比我聰明得多的研究員和工程師，詢問他們覺得眼下最重要的問題和解決方案是什麼。

> **編者注：** 也稱林迪效應（Lindy effect）。

第三，我也參考了林迪定律（Lindy's law）來判斷。簡單來說，該定律說的是：一項技術的預期壽命和它已經存在的時間成正比。因此，如果一項技術已經存在了很久，我就傾向於認為它還會繼續存在下去。

不過，本書偶爾也會包含一些我認為只是暫時性的概念，因為它們對某些應用開發者來說有直接幫助，或者展示了一種有趣的解決問題的思路。

## 本書不涉及的內容

本書不是一本教程。雖然書中提到了具體的工具，幷包含一些虛擬碼片段來說明某些概念，但它並不會教你如何使用某個工具。它提供了一種選擇工具的框架，包含大量關於在不同解決方案之間進行權衡的討論，以及在評估解決方案過程中你應該提出的問題。當你想使用某個工具時，通常很容易在網上找到相關教程。AI聊天機器人也能很好地幫助你快速上手流行的工具。

本書不是一本機器學習（ML）理論書。它不會解釋什麼是神經網路，也不會教你如何從零開始構建和訓練模型。雖然書中解釋了許多與所討論的主題直接相關的理論概念，但本書本質上是一本實踐書，重點在於幫助你構建成功的AI應用，以解決實際問題。

即使沒有ML專業知識也可以構建基於基礎模型的應用，但對ML和統計學的基本理解有助於你構建更好的應用，並避免不必要的困難。你可以在沒有任何ML背景的情況下閱讀本書，但如果你了解以下概念，在構建AI應用時會更加高效。

- 機率相關概念，例如取樣、確定性和分佈。
- ML相關概念，例如監督、自監督（self-supervision）、對數機率、梯度下降、反向傳播、損失函式和超參數調優。
- 各種神經網路架構，包括前饋神經網路、迴圈神經網路和Transformer。
- 評估指標，例如準確率、F1分數、精確率、召回率、餘弦相似度和交叉熵（cross entropy）。

如果你還不了解這些概念，也不用擔心——本書會提供簡要的概括性解釋或介紹相關資源，幫助你快速掌握。

## 如何閱讀本書

本書的結構遵循開發AI應用的典型流程。以下是典型的開發流程，以及各章如何對應到該流程中。由於本書採用模組化結構，你可以跳過任何你已經熟悉或與你相關性較低的部分。在決定構建AI應用之前，有必要了解這一過程涉及哪些內容，並回答以下問題：這個應用是否必要？是否一定需要用到AI？我是否必須親自構建這個應用？本書的第1章將幫助你回答這些問題，並介紹一系列成功的應用案例，以便你對基礎模型的能力建立直觀的認識。

雖然構建AI應用不一定需要ML背景，但理解基礎模型的內部運作機制有助於更好地利用它。第2章分析了基礎模型的構建過程，以及對下游應用產生重大影響的設計決策，包括訓練資料的選擇、模型架構與規模，以及如何訓練模型以使其符合人類偏好。接下來，這一章還討論了模型如何生成回應（response），這有助於解釋模型的一些看似令人困惑的行為，例如不一致性和幻覺現象。此外，調整模型的生成設定通常也是一種低成本且簡單的方法，能夠顯著提升模型的效能。

一旦決定使用基礎模型構建應用，評估將貫穿整個過程，成為其中的重要組成部分。評估是AI工程中最困難的挑戰之一（甚至沒有「之一」）。本書專門用第3章和第4章來探討不同的評估方法，以及如何利用這些方法為你的應用建立可靠且系統化的評估流水線。

給定一個查詢，模型回應的品質取決於以下幾個方面（不考慮模型自身的生成設定）。

- 引導模型行為的指令
- 模型用於回應查詢的上下文
- 模型本身

本書接下來的三章將分別關注如何最佳化上述每個方面，以改善模型在應用中的表現。第5章介紹提示工程，首先解釋什麼是提示詞、提示工程為何有效，以及提示工程的最佳實踐。隨後討論惡意攻擊者如何利用提示詞攻擊你的應用，以及如何防範這些攻擊。

第6章探討了上下文為何對模型生成準確的回應至關重要，並詳細介紹了兩種構建上下文的主要應用模式：RAG模式和智慧體（agentic）模式。RAG模式已經被廣泛理解，並且在實際生產環境中表現良好；而智慧體模式雖然潛力更大，但也更複雜，目前仍處於探索階段。

第7章講述如何透過微調模型本身來適配特定應用。由於基礎模型的規模龐大，直接對模型進行微調會佔用大量記憶體，因此人們開發了許多技術，以便在更少的記憶體下微調出更好的模型。這一章涵蓋了不同的微調方法，並介紹了一種更具實驗性的方式：模型合併（merging）。此外，還包含一個較為技術性的部分，展示如何計算模型的記憶體佔用。

鑑於目前已有許多微調框架可用，微調過程本身通常較為簡單。然而，獲取用於微調的資料卻很困難。第8章將專門討論資料，包括資料獲取、資料標註、資料合成和資料處理。其中討論的許多主題不僅限於微調，還涉及更廣泛的問題，例如資料品質的定義以及如何評估資料品質。

如果說第5章到第8章關注的是如何提高模型品質，那麼第9章則關注如何降低模型推理的成本並提高推理速度。這一章從模型層面和推理服務層面分別討論最佳化方法。如果你使用的是模型API（即由第三方託管的模型），API提供商通常會替你處理好推理最佳化的工作。但如果你自託管模型（無論是開源模型還是內部開發的模型），則需要實作這一章討論的許多最佳化技術。

本書的最後一章將整合前面各章的概念，端到端地構建一個完整的應用。這一章的後半部分更關注產品層面，討論如何設計使用者回饋系統，以便在保持良好使用者體驗的同時收集有用的回饋。
