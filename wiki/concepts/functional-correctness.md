## 概述

功能正確性是一種根據系統是否正確實現預期功能來進行評估的方法。與衡量文本表面相似度的指標不同，功能正確性關注的是輸出在功能層面是否達成目標。這種方法在程式碼生成、數學運算、結構化查詢等有客觀驗證手段的任務中特別有效。

## pass@k 指標

pass@k 是功能正確性評估中最具代表性的指標，由 OpenAI 在 HumanEval benchmark 中提出。其定義為：讓模型生成 k 個候選解答，只要其中至少一個通過所有測試用例，就算通過。pass@1 衡量的是模型單次生成正確答案的機率，pass@10 則允許多次嘗試，反映模型在多次取樣下找到正確解答的能力。這個指標的設計體現了一個重要理念：在實際應用中，我們往往可以生成多個候選方案再從中篩選。

## 程式碼生成的自動驗證

程式碼生成是功能正確性評估最成熟的應用場景。評估流程通常是：給定問題描述，讓模型生成程式碼，然後透過執行預先準備的測試用例來驗證正確性。這種方式完全自動化且客觀，不需要人類評審介入。HumanEval 與 MBPP 是這個領域最常用的 benchmark。

## 數學與 SQL 驗證

在數學問題方面，功能正確性透過比對最終答案（而非解題過程）來判定對錯，常見 benchmark 包括 GSM8K 和 MATH。在 SQL 生成方面，由於同一個查詢可能有多種等價寫法，評估需要比較**執行結果的語義等價性**，而非 SQL 語句本身的字面匹配。Spider 是 SQL 生成領域常用的評估資料集。

## 局限

功能正確性的主要限制在於它只適用於有明確驗證方式的任務。對於開放式文本生成、創意寫作、對話等任務，功能正確性無法直接適用，需要搭配 [[llm-as-judge]] 或 [[lexical-semantic-similarity]] 等方法。
