## 定義

AI agent（智慧體）是一種能感知環境並透過工具作用於環境的自主系統。其運作遵循感知-規劃-執行（Perceive-Plan-Act）迴圈：首先接收環境資訊與使用者指令，接著制定行動計畫，最後透過呼叫工具執行具體動作，再根據結果進入下一輪迴圈。與單純的語言模型問答不同，agent 具備主動性——它能決定使用哪些工具、以何種順序執行、以及何時停止。

## 工具的三大類型

Agent 可使用的工具大致分為三類。第一類是知識增強工具，如搜尋引擎、資料庫查詢、文件檢索（[[rag]]），讓 agent 能存取超出模型內部知識的資訊。第二類是能力擴展工具，如程式碼執行器、計算器、翻譯器，為 agent 賦予模型本身不擅長的技能。第三類是寫入動作工具，如發送郵件、建立工單、更新資料庫，使 agent 能真正改變外部世界的狀態。這三類工具的風險等級遞增——唯讀操作相對安全，寫入操作則需要嚴格的權限控制。

## 規劃與執行的解耦

成熟的 agent 架構強調規劃（planning）與執行（execution）的分離。若讓模型邊想邊做，一旦走入錯誤路徑就難以回頭，浪費大量運算資源。較好的做法是先讓模型制定完整計畫，經過驗證後再逐步執行。這種解耦也便於人類介入審核，在高風險操作前確認 agent 的意圖。[[react-framework]] 是實現這種推理與行動交替進行的代表性框架。

## 錯誤累積問題

Agent 系統面臨的核心挑戰之一是錯誤的累積效應。假設每一步操作的準確率為 95%，看似很高，但經過十步操作後整體成功率僅剩約 60%（0.95^10 ≈ 0.60）。這意味著越複雜的任務，agent 失敗的機率越高。應對策略包括：減少步驟數（合併操作）、在關鍵節點加入驗證、允許錯誤修正（如 Reflexion 框架）、以及設定合理的停止條件避免無限迴圈。

## 單 Agent vs. 多 Agent 架構

簡單任務適合單一 agent 處理，但複雜任務常需多個 agent 協作。多 agent 架構可以讓不同 agent 專精於不同領域，透過明確的通訊協定分工合作。然而，多 agent 系統也帶來協調成本與除錯難度的增加。

## 與 RAG 的關係

[[rag]] 可以被視為 agent 的一個特例——一個僅執行「檢索」這一種工具的唯讀 agent。從這個角度理解，agent 是 RAG 的泛化：它不僅能讀取資訊，還能透過 [[function-calling]] 執行各種動作。
