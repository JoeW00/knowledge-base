## 定義

Memory management 是管理 [[ai-agent]] 系統中短期與長期記憶的機制，決定了 agent 能「記住」什麼、「遺忘」什麼、以及如何在多輪互動中維持連貫性。記憶能力是將簡單的問答模型提升為能處理複雜、多步驟任務的智慧體的關鍵基礎設施。沒有良好的記憶管理，agent 在長對話中會逐漸「失憶」，重複相同的錯誤或遺忘使用者的偏好與先前的決策。

## 三種記憶類型

Agent 的記憶可分為三個層次。第一層是內部知識，即模型參數中編碼的訓練知識，這是「與生俱來」的記憶，無法在推理階段修改。第二層是短期記憶，對應模型的上下文窗口（context window），包含當前對話的歷史訊息，會隨著對話進行而不斷累積。第三層是長期記憶，儲存在外部系統（如資料庫、檔案系統）中，需要透過明確的讀寫機制存取。三層記憶各有其容量限制與存取成本，有效的記憶管理就是在這三者之間做出最佳的資訊配置。

## 上下文壓縮策略

短期記憶受限於上下文窗口的固定大小，當對話歷史超出窗口限制時就需要壓縮策略。最簡單的 FIFO（先進先出）策略直接丟棄最早的訊息，但可能遺失關鍵的早期資訊。摘要策略使用模型將舊對話壓縮為簡短摘要，保留核心資訊的同時大幅減少 token 佔用。選擇性保留策略則根據訊息的重要性決定保留或丟棄，例如始終保留 [[system-prompt]]、任務定義與關鍵決策節點，而壓縮或移除中間的探索性對話。實務上常結合多種策略——對近期訊息保留完整內容，對較早訊息進行摘要壓縮。

## 長期記憶的讀寫機制

長期記憶的實現需要明確的讀取與寫入介面。讀取機制通常基於 [[rag]] 的檢索技術——agent 將當前任務上下文作為查詢，從長期記憶庫中檢索相關的歷史資訊。寫入機制則需要 agent 主動判斷哪些資訊值得長期保存（如使用者偏好、重要決策、學到的經驗教訓），並以結構化的方式寫入外部儲存。寫入的時機與內容選擇是設計長期記憶系統的核心挑戰——過度寫入會導致記憶庫膨脹且檢索品質下降，寫入不足則失去長期記憶的價值。

## 記憶對多輪對話與複雜任務的重要性

在多輪對話中，記憶讓 agent 能追蹤對話主題的演變、記住使用者的指令修改、避免重複詢問已知資訊。在複雜任務中，記憶讓 agent 能記錄已完成的步驟、失敗的嘗試（如 Reflexion 框架的反思），以及從過往經驗中學習。對於 [[react-framework]] 等需要多步推理的架構，Observation 的累積本質上就是短期記憶的運用。

## 記憶生命週期視角

[[agent-memory-taxonomy]] 提出更精細的動態觀點：記憶管理的核心不只是讀寫機制，而是 [[memory-lifecycle]] 的三個過程——formation（從原始互動提取知識）、evolution（整合、去衝突、遺忘）、retrieval（依上下文客製化檢索）。短期與長期記憶的區別不來自架構分離，而來自這三個操作被觸發的時間模式。此觀點也預示了記憶管理從手工規則走向 RL 驅動的自動化趨勢。
